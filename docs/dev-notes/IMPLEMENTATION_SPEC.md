# IMPLEMENTATION_SPEC.md — Техническая спецификация к доработке Steam Torrent Finder

Назначение: техническое ТЗ для следующего AI-агента. Полный аудит с обоснованием каждого пункта — в `AUDIT.md`. Здесь — порядок выполнения, точные локации и критерии готовности. Правило для исполнителя: **сохранить работоспособность существующих трекеров; рефакторить только указанными кусками; не переписывать архитектуру поиска.**

---

## Phase 1 — Critical fixes

### 1.1 Экранирование href/magnet при рендеринге (CR-01, SC-02)

**Цель:** исключить HTML-инъекцию через атрибуты href из данных скрейпинга.
**Файлы:** `content.js` (строки 464-497), `background.js` (строки 79-87, код аппарата обогащения 537-588, 634-646, точки сборки магнитов 260, 309, 543, 641).
**Что изменить:**
- в `versionRow` и `fixCard` применить `escapeHtml()` ко всем интерполяциям в атрибутах: `href="${escapeHtml(r.magnet)}"`, `href="${escapeHtml(r.detailUrl)}"`, `href="${escapeHtml(d)}"`;
- в `escapeHtml()` добавить правило для `'` → `&#39;`;
- в background создать валидаторы и применять их в местах присвоения `magnet`/`detailUrl`:
  - `magnet`: `^magnet:\?xt=urn:btih:([a-fA-F0-9]{40}|[A-Z2-7]{32})` + параметры без `"`, `<`, `>`, `'`; невалидно → `magnet = null` (ссылка-заглушка не теряется, так как остаётся detailUrl);
  - `detailUrl`: `new URL()` + whitelist протоколов `http:|https:`; невалидно → `undefined`.
**Ожидаемое поведение:** все магниты/ссылки, попадающие в рендер, гарантированно не содержат кавычек/угловых скобок; разрыв атрибута невозможен.
**Критерии готовности:** фикстура с закодированными `&quot;`/`&#x3C;` в магнит/URL не порождает исполняемого разметке; все 5 встроенных трекеров отдают результаты как прежде.
**Побочные эффекты:** очень осторожно с легитимными магнитами, где хеш 64 hex (v2-битторрент) — выбрать whether допускать и `[a-fA-F0-9]{64}` (рекомендуется: допустить и 40, и 64 hex).

### 1.2 Куки только по whitelist (CR-02)

**Цель:** не отправлять браузерные куки произвольным доменам.
**Файлы:** `background.js` (строки 25-34, вызовы 288, 292, 342, 415, 540, 563, 601, 637).
**Что изменить:** `fetchWithTimeout(url, timeoutMs, opts)` — `credentials` отделять в явный параметр по умолчанию `'omit'`; добавить `const CREDENTIAL_HOSTS = new Set(['rutracker.org','freetp.org','online-fix.me'])`, при `new URL(url).hostname in CREDENTIAL_HOSTS` → `'include'`. Простая настраиваемость: экспортировать эту логику в helper (в Phase 5 переехать в `common.js`).
**Ожидаемое поведение:** на Rutracker работает по-прежнему (вход по кукам); на зеркалах TPB/apibay/1337x/кастомных — запросы без кук.
**Критерии готовности:** в DevTools SW ни один fetch на вне-whitelist хост не несёт Cookie; Rutracker для залогиненного юзера продолжает отдавать `torTopic`.
**Побочные эффекты:** если пользователь зависел от кук на 1337x/freetp (допустимо) — потери; развивать per-host настройку как follow-up, не блокирующий Phase 1.

## Phase 2 — Major fixes

### 2.1 Не ретраить честно пустые результаты (MJ-01)

**Цель:** «Ничего не найдено» максимально быстро; ретраи — только при реальных сбоях.
**Файлы:** `background.js` (строки 184-193, 222-515 — маркеры разметки; 674-688 — логика ретраев).
**Что изменить:**
- ввести контракт `runTracker`: если парсер вернул `{ kind:'empty', results: [] }` — ретрай не делать; если `{ kind:'unknown' }` (сеть/HTTP/ошибка парсинга) — ретратить максимум 2 раза;
- в каждом парсере внедить маркер живой разметки в contrast-случаях:
  - apibay: `[{id:"0"…}]` — уже есть (сейчас!) — «честно пусто»;
  - piratebay HTML: наличие `searchResult` и отсутствие магнитов — «честно пусто»; отсутствие `searchResult` — `unknown` (разметка изменилась);
  - 1337x: наличие `coll-1` и 0 совпадений строк — «честно пусто»; отсутствие маркера — `unknown`;
  - freetp/online-fix: наличие признака страницы результатов (напр. `.heading`/`.article clr` блок, или общий «текст «Обрано»»/«Найдено…»/`searchResults`); пропуске маркера — `unknown`;
  - customParser: наличие `<a href=...>` в целом — «честно пусто», полностью пустой html — `unknown`.
**Ожидаемое поведение:** экзотическая игра возвращает «ничего не найдено» за первые успехи ответов трекеров (~10-25 c), а не за минуту; трекер с поломанным сайтом показывает «не отвечает», а не ложное «пусто».
**Критерии готовности:** для каждого трекера — юнит-фикстуры «честно пусто», «unknown на сломанной разметке», «с результатами»; время до финального статуса заметно улучшено.
**Побочные эффекты:** риск ложно-пустого, если маркер разметки не найден — поэтому маркер ОТСУТСТВИЯ классифицируется как ошибка (обязательное правило). 

### 2.2 Activity-based watchdog (MJ-02)

**Цель:** не обрывать легальный поиск на 75 c.
**Файлы:** `content.js` (строки 249-256, `port.onMessage` 261-281).
**Что изменить:** watchdog востанавливать (сбрасывать и перезапускать) при каждом `trackerResult` и `started`; фиксированный потолок — `MAX_TOTAL_TIMEOUT = 120000` мс отдельным жёстким таймером.
**Ожидаемое поведение:** медленный поиск не получает ложного timeout, пока результаты реально приходят/финализируются; 2 мин — предохранитель.
**Критерии готовности:** на Slow 3G с freetp+x1337 поиск доигрывает без ложного timeout; принудительный watchdog срабатывает только при 120 c полного молчания.
**Побочные эффекты:** нулевые (detach только и размывает тайминги сообщений).

### 2.3 Инкрементальный рендер + делегирование событий (MJ-03, PF-03)

**Цель:** рендерится только узел приходящего трекера; клики — делегированно.
**Файлы:** `content.js` (297-315, 500-516, 519-544).
**Что изменить:** `#stf-groups` содержит на каждый трекер контейнер `<div class="stf-tracker-block" data-tracker="${key}">`; `renderIncremental` создаёт/заменяет только этот блок. Клик по `.stf-group-head` — через один слушатель на `#stf-groups` (closest). Таб-переключение — оставшаяся full-redraw (редкость), но её тоже можно изолировать. Один общий source компиляции `compileGroup(key, results, error)` — остаётся как есть.
**Ожидаемое поведение:** при каждом `trackerResult` пересобирается ровно один block; аккордеоновые состояния через `openGroups` сохраняются; остальные трекеры не дёргаются.
**Критерии готовности:** Performance-профиль: 1 Layout/RecalcStyle на `trackerResult` (не N); клик аккордеона работает без перезапуска слушателей.
**Побочные эффекты:** позиция скролла сохраняется при инкременте (блоки вне Portals уточняются без полного rebuild); нужно убедиться, что пере-формированный блок сохраняет `openGroups` (текущий Set уже обеспечивает).

### 2.4 Резолвинг относительных ссылок в customParser (MJ-05)

**Цель:** относительные href результатов тоже попадают в выдачу.
**Файлы:** `background.js` (610-618).
**Что изменить:** regex расширить до `<a\s[^>]*href="([^"#]+)"`; каждый href резолвить через `new URL(href, baseUrl)`; same-origin оставить через сравнение `new URL(...).origin === origin`.NULL — пропускать.
**Ожидаемое поведение:** кастомный трекер с relative-ссылками отдаляет результаты; same-site остаётся.
**Критерии готовности:** фикстура DLE-страницы с relative-ссылками — релевантные релизы в выдаче; посторонние origin-ссылки отброшены.
**Побочные эффекты:** возрастёт количество кандидатов релевантности — порог 65 остаются.

### 2.5 Обрыв лишних fetch зеркал TPB (PF-01)

**Цель:** максимум 1-2 fetch зеркального HTML на поиск.
**Файлы:** `background.js` (272-297, 674-688).
**Что изменить:** добавить «последний живой» хост — кэш successful; при повторных попытках сперва его. Вместе с MJ-01 (2.1) ретраить HTML-парсер только если есть `unknown`-сигнал. Необязательно два отдельных AbortController — при `Promise.any` решении остальные fetch уже догоняют, частично прерываются. Минимальный оправданный шаг: после hit ждать 1000 мс и затем форсировать abort проигравших (набор AbortController на mirrors-map).
**Ожидаемое поведение:** до 5 fetch параллельно, каждый из которых при хите быстрым interrupt; ретраи не умножаются.
**Критерии готовности:** TPB отдаёт результат за ≤7 c от frustrum-зеркала; в Network — ≤5 (+1-2 при ретрае) fetch зеркал.
**Побочные эффекты:** низкий.

## Phase 3 — UX/UI

### 3.1 Empty-state при abort-финализации (UX-01)

**Файлы:** `content.js` (344-363).
**Цель:** при обрыве показать empty-состояние пустой вкладки.
**Что изменить:** в `finalize` с `aborted=true`: не `return` сразу, а показать `emptyTabBlock` (с сохранением abort-сообщения в статусе).
**Критерии готовности:** закрывшаяся панель с аборт-сценарием: активная вкладка показывает либо результаты, либо empty-блок.
**Побочные эффекты:** нулевые.

### 3.2 Номер попытки в статусе (UX-03)

**Файлы:** `background.js` (689-698), `content.js` (305-315, t-key текст polled).
**Цель:** пользователь видит, что трекер пере-опрос зн.
**Что изменить:** `trackerResult` включает `attempt: n`; в статусе при `attempt>1` добавить `(попытка n)`.
**Критерии готовности:** при ретрае виден номер попытки.
**Побочные эффекты:** нулевые.

### 3.3 Кнопка «Проверить» для кастомного трекера (UX-04)

**Файлы:** `popup.html` (кнопка), `popup.js` (обработчик + нормализация ошибки), `background.js` (новый `chrome.runtime.onMessage`-енд-то `testCustom` → использует `customParser` на тестовом запросе с фиксированным `{q}`).
**Цель:** пользователь до добавления видит, живой ли шаблон.
**Что изменить:** кнопку `testCustomBtn` рядом с «Добавить»; обработчик: `chrome.runtime.sendMessage({type:'testCustom', conf})` → background делает single-феч запроса, возвращает `{ok, count, titles:[...]||error}`; popup показывает до 3 заголовков или ошибку.
**Критерии готовности:** добавляется test-фича; при невалидном шаблоне пользователь видит ошибку inline, а не на странице Steam.
**Побочные эффекты:** требует протокола сообщения в background (реализовать через `chrome.runtime.onMessage`, не мешая порт-стриму поиска).

### 3.4 Подпись при закрытии панели (UX-02, Cosmetic)

**Файлы:** `content.js` (I18N).
**Что изменить:** в подполе статус-строки добавить подсказку «Закрытие панели останавливает поиск» (ru/en), появляющуюся во время активного поиска.
**Критерии готовности:** подпись видна во время поиска; после done — скрыта/заменена статусом finished.
**Побочные эффекты:** нулевые.

## Phase 5 — Architecture

### 5.1 Единый `common.js` с дефолтами (MJ-04)

**Цель:** одна правда по трекерам/группам.
**Файлы:** новый `common.js`; модиф: `manifest.json` (`background.service_worker` → оставить `background.js`, но `importScripts('common.js')` сверху), `popup.html` + `content.js` (шаг: подключить `<script src="common.js">`-style, в MV3 content-скрипт можно подключить через `manifest.json` c приоритетом раньше content.js).
**Что изменить:** перенести в `common.js`: `DEFAULT_TRACKERS` (merged BUILTIN_META + enabled/color/group), `DEFAULT_GROUPS`, `TRACKER_COLORS`, `BUILTIN_META`; заменить во всех трёх контекстах на импорты.
**Ожидаемое поведение:** добавление нового трекера — правка одного файла.
**Критерии готовности:** во всех трёх контекстах работает; popup показывает, background ищет, content рендерит.
**Побочные эффекты:** риск: если структ. `groups`/`trackers` — migration случаи уже покрыты (`loadState`, `loadLayout`) — идеально. Прогнать тест (d) из AUDIT.md § Тесты.

### 5.2 Унификация enrich (MJ-06)

**Файлы:** `background.js` (537-588, 634-646).
**Что изменить:** `fetchPage(url, {enc})`; композиция Экстракторов: `enrich(results, opts={top:5, enc:null, extractors:[{re, map}]})`; преобразовать `x1337Enrich`/`freetpEnrich`/`grabMagnet` в использование единой функции.
**Критерии готовности:** функциональное содержание прежнее (магниты/даты/размеры добираются как раньше); regression-фикстуры.
**Побочные эффекты:** низкие.

### 5.3 Объект «сессия поиска» (не срочно)

**Файлы:** `content.js` (10-17, 196-294).
**Что изменить (опционально):** реорганизовать семь top-level переменных в объект активной сессии, управляемый `startSession()`/`stopSession()`. Выполняется ИСКЛЮЧИТЕЛЬНО если залеживание осталось после Phase 2/3 — приоритет низкий.
**Критерии готовности:** поведение не меняется; тест (c) из AUDIT.md исправно.
**Побочные эффекты:** риск race — выполнять с вниманием, оценив каждый используеможный catch.

## Phase 7 — Testing / regression

**Цель:** закрепить неизменность существующего поведения и новые фиксы.
**Файлы (новые):** `tests/` с минималистичным runner (мок `fetchWithTimeout` через injectable-фьюч; фикстуры HTML/JSON по трекерам).

### Что должно быть горячо протестировано
1. **Парсеры (юнит):** по фикстурам «честно пусто», «с результатами», «разметка сломана» → все 5 встроенных трекеров. Инвариант: «отсутствие маркера разметки» → ошибка (не пусто). (MJ-01 contract)
2. **XSS (юнит):** фикстура с `&quot;`/`<` внутри magnet/detailUrl → рендер без внедрения; escape-мид-атрибуты нетронуты. (CR-01)
3. **Магнит-валидация (юнит):** 40-hex магнит принимается, 64-hex допустим, кавычки — отброшены. (SC-01)
4. **Креды (юнит):** `buildFetchCreds(url)` для rutracker/freetp/online-fix — include; для остальных — omit. (CR-02)
5. **Эпоки/таймеры (интеграц., ручной или Playwright):** повторный клик во время поиска → нет сообщений старой эпохи; закрытие панели → таймеры сброшены; watchdog не жжёт раньше 120 c полного молчания. (MJ-02, тесты c/f из AUDIT)
6. **Popup-миграции (интеграц.):** создание/удаление/драг папок → сохранение → модалка показывает правильные вкладки; битые хранилища не ломаю. (тест d из AUDIT)
7. **Custom-парсер:** relative-ссылки; same-origin фильтр; grab-магнит на торой фазе. (MJ-05)
8. **Регресс предупреждений консоли:** init-retry/MutationObserver не генерируют при обычном супер-поведении. (MN-03)

### Сводные DoD (Definition of Done) на весь план
- Все 5 встроенных трекеров + кастомные: happy-path работает (фикстуры).
- Нет исполняемых инъекций из результатов.
- Худший time-to-first-result ≤10 c на нормальной сети; «честно пусто» ≤ 25 c.
- Watchdog активирует только после 120 c полного молчания.
- Popup: полное EN-локализование изменённых мест.
- Комбо-тест папок и «кэш» (если внедрён 6.1) — без рассинхронизации вкладок/поиска.
